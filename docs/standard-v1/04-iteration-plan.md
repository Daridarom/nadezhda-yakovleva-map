# Standard v1 — Iteration Plan

## Цель итерации
Не переделывать сайт заново. Довести существующую версию до более цельного, живого и запоминающегося состояния без потери уже согласованной структуры и фактической аккуратности.

## Stage 1 — Hero comparison
Подготовить 3 варианта первого экрана в одной и той же сетке:
- A — текущий кабинетный портрет;
- B — самый живой естественный портрет из последней подборки;
- C — более свободный/личный кадр, который сама Надежда считает «настоящей собой».

Сравнивать не «какой красивее», а по пяти критериям: узнаваемость, доверие, живость, читаемость текста, соответствие роли психолога.

Результат: выбранный hero без изменения остальной страницы.

## Stage 2 — Content rhythm
- сократить визуальную высоту блока документов;
- проверить, какие подписи можно сделать короче без потери фактов;
- дать визуальную паузу после «Обо мне» и перед «Пространством»;
- проверить, что одна секция = одна главная мысль;
- не добавлять новый контент на этом этапе.

Результат: страница воспринимается легче при том же количестве подтверждённой информации.

## Stage 3 — Motion hierarchy
Правило:
1. journey line — основной сквозной motion;
2. Morpho — локальный эмоциональный акцент;
3. логотип — преимущественно статичный;
4. hover/fade — только служебные микроанимации.

Для mobile: уменьшить число одновременно видимых движущихся элементов.

## Stage 4 — Technical polish
- проверить LCP hero-image;
- проверить вес локальных шрифтов и необходимость WOFF2;
- проверить все внешние изображения документов;
- проверить broken links;
- повторить 320/375/430/desktop QA;
- проверить keyboard/focus/reduced-motion;
- проверить OG-preview;
- проверить, что без JS остаются контент и контакты.

## Stage 5 — Independent acceptance
Другой проход/агент получает только Blueprint + preview и проверяет:
- факты;
- UX;
- mobile;
- accessibility;
- performance;
- безопасность;
- визуальную иерархию;
- CTA.

Вердикт: REJECT / CONDITIONAL PASS / PASS.

## Release gate
До main допускается только версия со статусом PASS.

Последовательность:
1. commit/tag candidate;
2. preview;
3. ручная проверка на iPhone/desktop;
4. smoke-test CTA, меню, маршрутов, карт и документов;
5. явное подтверждение владельца проекта;
6. merge в main;
7. проверка GitHub Pages после публикации;
8. rollback на предыдущий commit при критической ошибке.

## Что считаем успешным пилотом Standard v1
Пилот успешен, если после него:
- решения не живут только в чате;
- понятно, что является фактом, а что гипотезой;
- дизайнерский проход отделён от технической сборки;
- публикация не происходит до независимой приёмки;
- следующую итерацию можно продолжить без восстановления контекста из десятков сообщений.
